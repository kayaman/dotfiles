# Machine-local GPG signing key via git `include` — design

**Date:** 2026-06-13
**Status:** Approved (pending spec review)

## Problem

`user.signingkey` lives in `stow/git/.gitconfig`, which is symlinked to
`~/.gitconfig`. Because that file is tracked, the signing key — inherently
machine/identity-local state — becomes a committed value. Three half-built
mechanisms currently fight over it, and the conflict is why the repo "can
never sync properly":

1. **Tracked + symlinked config.** The key is committed, so every machine
   overwrites it on sync. The staged diff flip-flops between
   `34940358712F23FE` (active) and `8237E64F98A71AD8` (stale — not even in
   this machine's keyring).
2. **`.dotfilter` clean filter.** `signingkey\s*=.*` is a redaction pattern.
   When installed, `git add` rewrites the key to `# [REDACTED by dot-filter]`
   in the index, but `smudge = cat` cannot restore it. Result: HEAD is
   permanently ≠ working tree (status always dirty), and any machine that
   pulls receives a gitconfig with no signing key at all.
3. **`dotfiles.toml [git] signingkey`.** A third intended source of truth that
   nothing wires into git.

A **fourth** churn source: `scripts/setup-git.sh` configures git via
`git config --global user.signingkey/name/email` — and because `~/.gitconfig`
is the stowed symlink, every run rewrites the *tracked* `stow/git/.gitconfig`.

A related instance of the same disease: `stow/git/.githooks/pre-commit` is a
lefthook shim with a hardcoded `/home/kayaman/...` absolute path that also
flip-flops on every machine, reached via `core.hooksPath = ~/.githooks`.

## Core principle

**Nothing in this repo may write to `git config --global`**, because the global
file *is* a tracked, stowed file. Every machine-local write — `user.signingkey`,
and `user.name`/`user.email` when set interactively — targets the untracked
include file `~/.config/git/local.gitconfig` instead.

## Goals

- The tracked repo is byte-identical on every machine — no per-machine churn.
- Each machine derives its own signing key automatically.
- An explicit override exists for when auto-detection is ambiguous.
- Remove the global git hook entirely (decision below).

## Non-goals

- Changing how true secrets (tokens) are handled. `.dotfilter` stays for those.
- Per-repo hooks. Removing the *global* hook does not touch any repo's
  `.git/hooks`.

## Design

### 1. Tracked `.gitconfig`: drop the key, add an include

In `stow/git/.gitconfig`:

- Remove the `signingkey = …` line from `[user]`.
- Keep `commit.gpgsign = true`, `tag.gpgsign = true`, `gpg.program = gpg2`
  (machine-independent).
- Add at the end:

  ```
  [include]
      path = ~/.config/git/local.gitconfig
  ```

Git expands a leading `~/` in `include.path` and merges the included file, so
`[user] signingkey` defined there fills in. A missing include file is silently
ignored by git — so a fresh machine that hasn't generated it yet simply has no
key set (signing fails loudly at commit time, which is the correct signal).

### 2. Machine-local file (untracked, outside the stow tree)

`~/.config/git/local.gitconfig` — a **real file**, not a symlink, living
outside `stow/` so the dotfiles repo never tracks it. Generated content:

```
# Generated by dotfiles — machine-local, do not edit by hand.
# Regenerate: dot gpg-sync   (or re-run install.sh)
[user]
	signingkey = <KEYID>
```

Generation is idempotent: overwrite on each run.

### 3. Key resolution (shared logic)

A single shared bash script, `scripts/git-signingkey.sh`, is invoked by both
`install.sh` (bash) and `dot` (zsh) to avoid duplicated logic across the two
languages. It reuses the same NUL-delimited python `tomllib` parser already in
`setup-git.sh` to read the optional pin. It prints the resolved long key id to
stdout, or exits non-zero with a diagnostic on stderr. With `--write` it also
writes `~/.config/git/local.gitconfig`. Resolution order (decision: **pin in
dotfiles.toml, else newest**):

1. **Explicit pin.** If `dotfiles.toml [git] signingkey` is set and non-empty,
   use it verbatim. (Empty string `""` counts as unset.)
2. **Auto-detect.** Otherwise read the identity email (`git config user.email`,
   falling back to `dotfiles.toml [git] email`) and run
   `gpg --list-secret-keys --with-colons <email>`. Collect every `sec:` record;
   key id is field 5, creation timestamp is field 6.
   - Exactly one match → use it.
   - Multiple matches → pick the **newest** (max field 6) and emit a warning
     naming the chosen key and how to pin via `dotfiles.toml`.
   - Zero matches → exit non-zero with a message pointing at
     `dotfiles.toml [git] signingkey`. No file is written/overwritten.

A thin writer (in `install.sh` and `dot`) calls the script, and on success
writes `~/.config/git/local.gitconfig` (creating `~/.config/git` if needed).
If `gpg` is not installed, warn and skip without failing the install.

### 4. Wiring

- **`install.sh`**: new step `setup_git_signingkey`, called from `main` *after*
  `symlink_dotfiles` (so the include line is already in place). Always-on (not
  a toggle component); guarded so a missing `gpg` only warns.
- **`dot`**: new subcommand `dot gpg-sync` that regenerates the local file.
  `_dot_update` calls it after re-stowing. `dot help` gains a one-line entry.
- **`scripts/setup-git.sh`**: redirect its `git config --global` writes for
  `user.signingkey` (and the `user.name`/`user.email` it sets interactively)
  to `git config --file "$HOME/.config/git/local.gitconfig"`, so the
  interactive path stops mutating the tracked symlink. Its existing
  `commit.gpgsign`/`tag.gpgSign` toggles also move to the local file (or are
  dropped, since the tracked config already sets them).

### 5. Retire the redaction pattern and update the doctor check

- **`.dotfilter`**: remove the `signingkey\s*=.*` line. The key no longer lives
  in any tracked file, so redaction is unnecessary and was the churn source.
  All token/secret patterns stay.
- **`_dot_doctor`**: replace the `dotfiles.toml` signingkey probe (check #5)
  with: `git config user.signingkey` is non-empty **and** that id appears in
  `gpg --list-secret-keys` output. PASS if resolvable, WARN with
  `run: dot gpg-sync` otherwise.
- Update stray references in `dot help` text that point users at the old
  `signingkey` flow.

### 6. Remove the global git hook (decision: remove entirely)

- Delete `stow/git/.githooks/` (the tracked lefthook shim).
- Remove `hooksPath = ~/.githooks` from `[core]` in `stow/git/.gitconfig`.
- On already-provisioned machines, `~/.githooks` is a stale stow symlink;
  `install.sh`'s existing broken-symlink cleanup removes it on next run. Note
  this in the implementation plan so it isn't a surprise.

Per-repo `.git/hooks` are unaffected.

## Data flow

```
install.sh / dot gpg-sync
        │
        ├─ scripts/git-signingkey.sh
        │     ├─ dotfiles.toml [git] signingkey set?  ──► use it
        │     └─ else gpg --list-secret-keys <email>  ──► newest sec key
        │
        └─ write ~/.config/git/local.gitconfig  (real file, untracked)
                        │
   ~/.gitconfig (tracked) ── include ──►  [user] signingkey = <KEYID>
                        │
                   git commit -S
```

## Error handling

| Condition | Behavior |
|-----------|----------|
| `gpg` not installed | Warn, skip generation, do not fail install. |
| 0 keys match email, no pin | Exit non-zero, point at `dotfiles.toml`. Existing local file left intact. |
| 2+ keys match, no pin | Pick newest, warn with chosen id + pin instructions. |
| Pin set in dotfiles.toml | Use verbatim, no gpg query. |
| Include file absent at commit | git ignores include; signing fails loudly — correct signal to run `dot gpg-sync`. |

## Testing

- **Unit (`scripts/git-signingkey.sh`)**: feed canned `--with-colons` fixtures
  via a stubbed `gpg` on `PATH`; assert single-match, multi-match-newest,
  zero-match-exit, and pin-override paths.
- **Integration**: in a temp `HOME`, run the writer, then assert
  `git config user.signingkey` resolves through the include to the expected id.
- **doctor**: stub `gpg` so the resolved key is / isn't present; assert
  PASS vs WARN.
- **Idempotency**: run generation twice; second run leaves the file unchanged.

## Files touched

- `stow/git/.gitconfig` — drop `signingkey`, drop `hooksPath`, add `[include]`.
- `stow/git/.githooks/` — deleted.
- `scripts/git-signingkey.sh` — new shared resolver (+`--write`).
- `scripts/setup-git.sh` — redirect `--global` writes to the include file.
- `install.sh` — new `setup_git_signingkey` step + `main` wiring.
- `stow/zsh/functions.d/dot.zsh` — `dot gpg-sync`, `_dot_update` call,
  `_dot_doctor` check, help text.
- `.dotfilter` — remove `signingkey` pattern.
- `dotfiles.toml.example` — clarify `[git] signingkey` is the optional pin.
- `tests/git-signingkey.test.sh` — new; stubbed-`gpg` unit checks.
